## 1. Problem statement

Windows maintenance knowledge is trapped in three places: tribal IT memory, ad-hoc
"PC cleanup" scripts of unknown provenance, and a dozen Microsoft tools (`sfc`, `dism`,
`winsock reset`, `winget`, `Spooler`, `ipconfig`) that each have their own failure semantics.

The result is four recurring, expensive failures:

| Failure | Who pays | Evidence of cost |
| :--- | :--- | :--- |
| **F1 - The mystery slowdown.** A user's laptop "got slow"; nobody can say whether it is disk, RAM, a hung Office process, a VPN proxy lock, or a broken icon cache. | Employee time, helpdesk time | One ticket, one remote session, usually unresolved |
| **F2 - The unrecoverable cleanup.** Someone runs a "cleaner" that deletes the print queue, the icon cache, or Temp, and now nothing can be restored because nothing was backed up. | Re-image or manual rebuild | Hours per incident |
| **F3 - The reboot-loop repair.** IT runs `sfc /scannow` before `DISM /RestoreHealth`, SFC finds corruption it cannot fix, and the machine needs a second pass. | Double the maintenance window | 30-90 min wasted |
| **F4 - The blind fleet.** After a remediation, nobody can prove what changed, on which machine, with what result. | Audit and compliance exposure | Unanswerable during incident review |

Existing consumer cleaners optimise for a satisfying animation and a scary number of "GB
cleaned". They are unauditable, they over-promise reversibility, and IT departments ban them.
Existing enterprise tools (SCCM, Intune, NinjaOne) are excellent at *deploying* remediation but
provide almost no *deterministic local diagnostic* with honest reversibility semantics.

**Zenith occupies that gap:** a fast, local, auditable, honestly-labelled system doctor that a
power user will actually open, and that an IT department will allow.

---

## 2. Vision

> **A system utility that tells the truth about what it will do, proves what it did, and never
> leaves a machine worse than it found it.**

Three product laws follow, and they are requirements, not slogans:

| Law | Consequence |
| :--- | :--- |
| **Truth over comfort** | Every action declares one of four reversibility tiers. No action claims 100% rollback. Irreversible actions say so before the click. |
| **Evidence over animation** | Every number on screen is measured from the OS, with units and a source. No invented "health score" theatre: the formula is published in-app. |
| **Exit over lock-in** | Any selection can be exported as a readable PowerShell or Batch script and run without Zenith installed. |

## 3. Target users

Two primary segments, deliberately different. The product must satisfy both without becoming two
products.

### 3.1 Primary segment A - "The Responsible Power User" (consumer / prosumer)

- Developer, designer, gamer, or technically confident professional on a personal or
  small-business Windows machine.
- Runs Docker/WSL, JetBrains, VS Code, Teams, Adobe, games.
- Has been burned by a cleaner before.
- Buys software with a card, once, if the price is defensible.

**What they need:** one screen that says what is wrong, one button that fixes the safe things,
and a visible undo.

### 3.2 Primary segment B - "The Overloaded IT Generalist" (SMB / MSP)

- Manages 20-500 Windows endpoints alone or in a team of three.
- Lives in a ticket queue; cannot re-image every slow laptop.
- Needs to attach something to a ticket that a manager will accept.
- Cares about: auditability, scriptability, no surprise reboots, no unsigned binaries.

**What they need:** deterministic remediation they can run, an exportable script for machines
without Zenith, an audit trail, and a "safe preset" they can hand to a non-technical colleague.

### 3.3 Anti-personas (explicitly not optimised for)

| Anti-persona | Why not |
| :--- | :--- |
| The "one-click speed booster" shopper | Wants a fake number and RGB. Zenith's honesty is a feature for everyone else. |
| A managed enterprise with full Intune control | They will use Zenith's script export inside their own pipeline, not the GUI. Served by the CLI, not the desktop shell. |
| A user who wants Zenith to modify Windows beyond repair | Out of scope by design; the action set is closed and audited. |

## 5. Product principles that constrain engineering

| # | Principle | Where enforced |
| :--- | :--- | :--- |
| P1 | **No action without a reversibility tier and a pre-state.** | `03-05`, REQ-F-020 |
| P2 | **Destructive actions are never in the safe preset.** | `03-05` §5 matrix, REQ-F-031 |
| P3 | **Every long operation is cancellable and time-boxed.** | REQ-N-012, `03-06` §4 |
| P4 | **The UI never lies about elevation.** Standard-user sessions see what will require UAC *before* acting. | REQ-F-014 |
| P5 | **The app is fully usable with the keyboard alone.** | `05-03` §5 |
| P6 | **Localisation is not a post-launch translation pass.** | `06-01` |
| P7 | **Simulation mode is loudly labelled.** Any build without the native host shows `SIMULATION MODE - NO OS CHANGES`. | REQ-F-080 |
| P8 | **Uninstall leaves no orphaned state.** | `04-02` §6 |

## 6. Scope of v1.0.0

### 6.1 In scope

| Area | Content |
| :--- | :--- |
| Diagnostic engine | 22 actions across 4 categories, each with a real OS probe |
| Execution engine | transactional snapshots, 4-tier reversibility, cancellation, timeouts |
| Recovery | registry/service/file rollback with integrity verification |
| Interface | single-window desktop app, 10 components, 3 themes, full keyboard |
| Portability | PowerShell + Batch export of any selection |
| Operations | headless CLI, elevation handover, audit log, support bundle |
| Localisation | ICU plurals, structural parity, `en` + `tr` shipped (ADR-023) |
| Trust | Authenticode signing, signed auto-update, SBOM |

### 6.2 Explicit non-goals (guarded by the Zero-Stub Law)

| Non-goal | Reason | Future home |
| :--- | :--- | :--- |
| Driver installation / updates | Requires WU driver APIs, high brick risk | v2 |
| Registry cleaning ("optimise" arbitrary keys) | Unsafe by nature; no honest reversibility | never |
| Disk defrag / TRIM scheduling | Windows already owns this; no user value | never |
| Antivirus / malware scanning | Different product and liability class | never |
| Remote fleet management GUI | Enterprise tier is telemetry + scripts, not RMM | v2, `09-01` |
| macOS / Linux targets | Product is Win32-deep by design | never |
| Plugin system | Attack surface on an elevated binary | v3, needs threat model |
| Account system / cloud sync | Local-first is the moat | never |

## 7. Success metrics

Two dashboards. Consumer metrics are honest-product metrics; enterprise metrics are the ones a
buyer asks for in the first meeting.

### 7.1 Product health (leading, measured in-app with consent)

| ID | Metric | Target at 90 days | Instrumentation |
| :--- | :--- | :--- | :--- |
| KPI-1 | Diagnose-all completion rate (not cancelled, < 10 s) | ≥ 92% | Local event counter |
| KPI-2 | Safe-preset success rate (all steps succeed) | ≥ 95% | Audit log aggregate |
| KPI-3 | Rollback success rate on reversible actions | ≥ 98% | Audit log aggregate |
| KPI-4 | Crash-free sessions | ≥ 99.5% | Crash reporter |
| KPI-5 | Actions per active user per month | ≥ 6 | Local counter |
| KPI-6 | Users who open Snapshot History after a rollback-capable action | ≥ 35% | UI event |
| KPI-7 | Median time-to-first-successful-remediation for a new user | ≤ 90 s | Session funnel |

### 7.2 Business and trust (lagging)

| ID | Metric | Target | Note |
| :--- | :--- | :--- | :--- |
| KPI-8 | 30-day retention (consumer) | ≥ 40% | Requires sticky monthly job |
| KPI-9 | Free → Pro conversion | 3-6% | Deliberately not aggressive paywalling |
| KPI-10 | Support tickets per 1,000 installs | ≤ 8 | Quality proxy |
| KPI-11 | SmartScreen / AV false-positive rate | 0 | Requires EV signing + reputation |
| KPI-12 | Enterprise pilot → paid | ≥ 30% | Fleet tier |
| KPI-13 | Median ticket-resolution time saved (self-reported, SMB) | ≥ 20 min/incident | Survey |

### 7.3 Anti-metrics (things we refuse to optimise)

- **Bytes "cleaned" per session** - incentivises deleting user data.
- **Session length** - a maintenance tool should be fast and closed.
- **Notification volume** - no nagging, no upsell popups.

## 10. Packaging and licensing

Open-core, as in v1.0.0, but with the commercial boundary actually specified (`09-01`).

| Tier | Price | Contents | Licence |
| :--- | :--- | :--- | :--- |
| **Free** | $0 | All 22 actions, all diagnostics, snapshot + rollback, script export, every shipped locale (`en`, `tr`) | MIT (core) |
| **Pro** | $19 one-time, 1 year of updates, then optional renewal | Pro adds: scheduled safe-preset runs, extended snapshot retention (90 d), priority support | Commercial EULA |
| **Fleet** | $6/seat/month, min 25 | Aggregate telemetry dashboard, policy profiles, MSI transforms, offline licence | Vellium Commercial |
| **Source** | - | Core engine under MIT. The `enterprise-telemetry` cargo feature is **not implemented in 1.0.0** (`09-01` is a specification; DEF-060), so no Free or paid 1.0.0 build links any telemetry transport | MIT |

Rationale: the free tier must solve the user's problem completely, because trust is the product.
Pro sells *convenience over time*, Fleet sells *visibility across machines*. Neither gates safety.

## 11. Constraints and dependencies

| Constraint | Impact | Mitigation |
| :--- | :--- | :--- |
| Windows-only, Win32-deep | No cross-platform reuse | Accepted; the moat |
| Elevated operations require UAC | Interrupts flow | Pre-flight elevation panel, single re-launch, queue resume (`03-04` §5.4) |
| WebView2 runtime dependency | Blank window risk | `downloadBootstrapper` + offline installer in `resources/installers` |
| Antivirus heuristics on process termination / registry writes | False positives | EV signing, submission to Microsoft, no packed binary, documented behaviour |
| Windows 10 ESU end-of-life | Shrinking base | Detect and inform; no broken promises on 19045 |
| Locale breadth without a translation vendor | Quality risk | Tiered locales + fallback + glossary (`06-01` §7); 1.0.0 ships only reviewed locales |
| No cloud backend in v1 | No server-side crash aggregation by default | Local support bundle + opt-in |

## 12. Release criteria (product-level)

A build may ship as 1.0.0 only if all hold:

1. All `Must` stories pass acceptance criteria in `02-01`.
2. Scorecard gates G1-G6 remain true at release (`00-01` §6).
3. Zero P1/P2 defects; zero open RED in `10-02`.
4. Signed installer verified on a clean Windows 11 24H2 VM and a Windows 10 22H2 VM.
5. 73-locale validation passes; RTL smoke test passes for `ar`, `he`, `fa`, `ur`.
6. Rollback verified for all 12 reversible-tier actions on real hardware.
7. Support bundle contains no secret material (test with a seeded token).
8. Uninstall leaves no files outside documented locations.
