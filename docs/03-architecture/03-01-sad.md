## 1. Architectural drivers

Architecture here is derived from constraints, not taste.

| # | Driver | Source | Consequence |
| :--- | :--- | :--- | :--- |
| D1 | Operations are privileged, destructive and irreversible in some cases | PRD P1/P2 | Strict layering: no UI code may touch the OS; all privilege in one trusted core |
| D2 | Users must be able to prove what happened | JTBD-10 | Append-only audit + content-addressed archives + correlation ids |
| D3 | A UI action must never block the UI | NFR-004 | All OS work off the webview thread; events, not returns, for streams |
| D4 | Elevation changes the process, not the app | REQ-F-093 | Machine-wide store; single-execution ownership; queue handover |
| D5 | Multiple locales without a backend service | REQ-F-120 | All strings local; backend speaks keys, not prose |
| D6 | Windows-only, Win32-deep | PRD §6.2 | `unsafe` isolated behind adapters with invariants |
| D7 | Deterministic builds and auditability | REQ-N-090..095 | Lockfiles, pinned toolchain, generated contracts |
| D8 | Must survive a crash mid-operation | REQ-F-025 | Write-ahead transactional archiving; recoverable state machine |

| Container | Responsibility | Must not |
| :--- | :--- | :--- |

| Rust core | Diagnose, execute, snapshot, rollback, audit | Contain UI copy |
| Store (SQLite WAL) | Persist snapshots, audit, settings | Store secrets or file contents |
| Archive store (ZIP) | Reversible file payloads | Be the source of truth (DB is) |
| CLI mode | Same core, no webview | Duplicate action logic |

### 4.1 Component responsibilities and invariants

| Component | Owns | Invariant |
| :--- | :--- | :--- |
| `ipc::validate` | Argument validation | Every payload validated before any engine call; no default-allow |
| `engine::executor` | Phase state machine | Exactly one action runs machine-wide; every transition is logged |
| `engine::snapshot` | 4-phase archive | A DB row exists **before** the first destructive mutation |
| `engine::audit` | Append-only log | Never mutated after write; bounded by prune only |
| `engine::retention` | Caps | Never deletes unrestored row without consent |
| `adapters::proc` | Process identity | Kill only after `(pid,name,start)` match in the same snapshot |
| `adapters::shell_iso` | Child processes | Every child in a job object; both pipes drained; cancellable |
| `adapters::uac` | Elevation | Handover authenticated; queue echoed back, never trusted blindly |

## 6. Runtime behaviour

### 6.1 Execution phase machine

```text
Idle ──diagnose──► Diagnosing ──► Healthy | NeedsAttention
                                        │
                                        └──execute──► Running ──► Success
                                                       │  ├────► Error
                                                       │  ├────► Cancelled
                                                       │  └────► SkippedDependency
Success ──rollback──► Running ──► RolledBack
```

Legal transitions are asserted in `engine::executor`; an illegal transition is a bug that returns
`InvalidTransition` and is logged, never silently coasted.

### 6.2 Cold start sequence

```text
1 main() → single-instance check → config load → log init
2 open DB (WAL) → integrity check → migrations
3 recover_incomplete_transactions() + retention.orphan_gc()
4 window create (hidden) → spawn webview → load bundle
5 webview ready → emit state_ready with cached telemetry
6 background: run read-only diagnosis (parallel, 3 workers, 2 s budget each)
7 emit telemetry_update → window shown
```

Target: interactive by step 5, useful by step 7 (REQ-N-001).

### 6.3 Diagnose-all sequence

```text
UI      core                     adapters
 │ invoke diagnose_all           │
 ├──────────────────────────────►│ validate
 │                              │ spawn_blocking(pool=3)
 │                              ├─► probe A ─┐
 │                              ├─► probe B ─┤ (each ≤2s, cancel token)
 │                              ├─► probe C ─┘
 │ ◄── event telemetry_update ───┤ aggregate → health index
 │ ◄── event diagnose_progress ──┤ after each probe
 │ ◄── return DiagnosticReport[] ┘
```

### 6.4 Long-running action sequence (`sfc`)

```text
UI                    executor               shell_iso              OS
 │ execute(action)      │                       │                   │
 ├─────────────────────►│ validate + admin check│                   │
 │                      ├─ snapshot (if any) ──►│                   │
 │                      ├─ create cancel token  │                   │
 │                      ├──────────────────────►│ spawn in job obj ─┼─► sfc.exe
 │ ◄─ event phase(Running)                      │                   │
 │ ◄─ event terminal_log ◄── decoder ───────────┤ read stdout+stderr│
 │ ◄─ event terminal_log ◄──────────────────────┤                   │
 │ invoke cancel ──────►│ set token ───────────►│ terminate job ────┼─► (tree)
 │ ◄─ event phase(Cancelled)                    │                   │
 │ ◄─ return ExecutionOutcome                   ┘                   │
```

### 6.5 Concurrency and locking

| Lock | Scope | Purpose |
| :--- | :--- | :--- |
| Single-instance guard (`tauri-plugin-single-instance`) | Machine | A second launch focuses the first window and exits, so only one process - and therefore only one executor - can exist (REQ-F-005, REQ-N-020) |
| `ExecutionRegistry` (in-memory `Mutex`) | Process | One *executing* action at a time; second call returns `ALREADY_RUNNING` |
| `Mutex<Connection>` | Process | SQLite access serialisation |
| `ActionRegistry` (in-memory, `RwLock`) | Process | Phase map per action |
| Snapshot file lock (`.lock`) | Machine | Prevent two writers to the same archive |
| Cancel registry | Process | `AtomicBool` per running action id |

Machine-wide single execution is enforced by **process singularity**, not by a shared named
mutex: the single-instance plugin makes a second process exit before it can open the database,
so the process-wide registry is machine-wide in effect. `src-tauri/src/lib.rs` has a test
(`single_instance_guard_is_wired`) that fails if the plugin call or the registry claim is
removed, so this row cannot drift back into prose.

Never held across `.await`; DB work inside `spawn_blocking`.

### 6.6 Threading model

| Thread | Work | Rule |
| :--- | :--- | :--- |
| Main (Tauri) | Window, IPC dispatch | Never blocks on I/O |
| Tokio blocking pool | FFI, DB, file, child management | Bounded (default 8, cap by env) |
| Reader threads | stdout/stderr pumps | One per pipe, joined on drop |
| Watchdog | Timeout enforcement per action | Fires cancel token |
| UI thread | React render | No sync native calls |

## 7. Algorithms

### 7.1 Snapshot transaction (write-ahead)

```text
Phase 0  validate scope + free disk check (REQ-F-142)
Phase 1  write archive to <name>.zip.tmp, preserving relative paths
Phase 2  reopen, iterate entries, CRC check, hash file → sha256; fsync; rename → .zip
Phase 3  INSERT snapshot row (COMMITTED, hmac) - the commit point
Phase 4  perform destructive mutation (delete / recycle / registry write)
```

Crash analysis:

| Crash after | On restart | User impact |
| :--- | :--- | :--- |
| Phase 1 | delete `.tmp`, no row | Nothing changed |
| Phase 2 | delete `.tmp`, no row | Nothing changed |
| Phase 3, before Phase 4 | row exists, mutation not applied | Consistent; rollback is a no-op verified by hash |
| Phase 4 partial | row exists, mutation partial | **rollback completes it**; audit marks partial |
| Phase 4 complete | normal | Reversible |

This is the honesty claim: **the commit point precedes the damage**.

### 7.2 Dependency ordering (Kahn)

```text
indegree map from dependsOn
queue = nodes with indegree 0 (stable order by manifest index)
while queue not empty: pop → emit → decrement successors
if emitted < total → CyclicDependencyDetected
```

Fail-fast: when a node ends `Error`, mark all transitive successors `SkippedDependency`.

### 7.3 Health index

```text
S = clamp(100 − (30·min(1, J_MB/5120)
              + 15·min(1, max(0, L_ms−50)/250)
              + 25·min(1, max(0, M%−75)/20)
              + 30·min(1, F/6)), 0, 100)
```

`F` = count of actions with `needs_attention`. Penalty weights are constants in one module and are
shown to the user in the score detail popover, because a score you cannot explain is a lie.

An input that could not be measured contributes no penalty and is not scored as healthy either: the
term is simply absent (`None`), and the UI shows `-` rather than a number it did not read. DNS latency
and memory use are both `Option` for this reason. A failed memory read once arrived as `0 %`, which
the strip rendered as "0 %" - the most reassuring figure on the screen - on a machine nobody had
actually looked at.

`severity_weight` is consumed here: an action's contribution to `F` is weighted by
`severity_weight/3`, rounded half-up, so HIGH-severity issues count more than LOW.

### 7.4 Redaction

Token-based scan over argv: match key patterns (`key|token|secret|password|passwd|pwd|auth|sig|
credential|connection|dsn`), strip `--flag value`, `--flag=value`, `-p<value>`, URL userinfo, and
long high-entropy literals. Fails closed: unknown-shaped long values become `***`.

## 8. Simulator mode architecture

```text
bridge.ts
  if (window.__TAURI_INTERNALS__) → tauriAdapter (real invoke/events)
  else                            → simulatorAdapter (deterministic)
```

Simulator contract:

- Same method signatures as the native adapter (compile-time checked by a shared interface).
- Seeded PRNG so snapshots are reproducible in tests.
- Simulated snapshots live in `localStorage` under `zenith.sim.snapshots.v1`.
- Every action resolves in 300-1800 ms with plausible logs.
- `cancel` honours the same timing model.
- **No import of any native module** (test asserts the module graph).

## 9. Error architecture

```text
ZenithError
├── User-fixable   ElevationRequired, ActionAlreadyRunning, DiskSpaceInsufficient,
│                  AlreadyRestored, AccessDenied
├── Environment    OperationTimedOut, Win32ApiFailure, ServiceUnavailable,
│                  ToolMissing (winget/sfc absent)
├── Integrity      SnapshotIntegrityError, ZipTraversalBlocked, HmacMismatch
├── Validation     InvalidArgument, InvalidTransition, CyclicDependencyDetected,
│                  ScopeViolation, PidVerificationFailed
└── Internal       Database, Io, Serialization, Zip, LockPoisoned, NotImplemented
```

Serialisation contract: `{ code, message_key, params, correlationId, remedy_key }`.
The webview resolves `message_key`; the Rust side never emits English prose to the UI (REQ-F-124).

## 10. Security architecture (summary; full in `04-01`)

| Layer | Control |
| :--- | :--- |
| Process | Signed binary; single instance; no remote content loaded |
| IPC | Typed commands only; no shell strings; per-command validation; re-checked elevation |
| Storage | Machine-wide dir with Administrators+SYSTEM ACL; DPAPI-protected HMAC key |
| Rollback | Per-action path allowlist; sha256 archive verify; zip-slip guard; HMAC tag |
| Elevation | Nonce handshake; caller SID check; queue never trusted |
| Child processes | Job object; explicit argv; no shell interpolation |
| Network | No egress by default; update manifest signature verify |

| ADR | Decision |
| :--- | :--- |
| 001 | Tauri 2 + React 19 single-window shell |
| 002 | Machine-checkable distributed authority instead of `.rules` |
| 003 | Write-ahead snapshot commit before mutation |
| 004 | Four honest reversibility tiers |
| 005 | Machine-wide store to defeat UAC split-brain |
| 006 | DPAPI-protected HMAC instead of MachineGuid-derived key |
| 007 | Allowlisted rollback scopes |
| 008 | Job objects for child process trees |
| 009 | ICU MessageFormat instead of flat key/value |
| 010 | Backend emits message keys, not prose |
| 011 | Manifest as single source of truth with codegen |
